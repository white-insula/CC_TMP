## 一、计划重检:4 个系统性缺口(2026-10-27)

计划骨架扎实(硬约束清晰、格式后置、校企=海康、practice-first、pilot 方法已验证)。但有 4 个
**系统性缺口**,ch02 失分只是第 1 个的局部症状:

1. **🔴 全书无"技能依赖图"。** ch02 翻车根因(`shape→坐标`:练习考了、正文没教)不是 ch02 独有,
   是 OUTLINE 层面就缺"每个练习用到的技能必须在上游教过"的保证。往下风险更大:ch03 一章塞
   HSV+`inRange`+掩膜+`findContours`、ch04 要"把 ch03 套到每一帧"、ch05/06 跳到模型。
   **没有依赖图,隐藏前置技能会反复咬人。** → 把"对账"从**事后**升级为**全书事前不变量**(见二、三)。
2. **🟠 资源数量不在轨道。** 硬指标 微视频≥80 / 虚仿≥6 / 动画≥369s;ch02 只挂 3 个资源点
   (1 微课+1 交互+1 虚仿)。按此密度 ×9 ≈ 27,**微视频离 80 差一大截**。要么每章资源密度数量级提升,
   要么 ≥80 口径重对。**此事会在 11 月前炸,需尽早面对。**
3. **🟠 代码环境未钉死且可能不兼容。** pilot 两名学生跑 **OpenCV 5.0.0**、一人用 Py3.11(须知写 3.9.11)。
   全书代码**没在锁定环境真跑过**。OpenCV 5.0 会改 API = 定时炸弹。
4. **🟡 未对齐职业教育标准。** 计划锚定"双高任务",未锚定**专业教学标准 / 1+X 机器视觉(计算机视觉应用)
   职业技能等级标准**——"什么算学会"本应由它定义,出版社三审三校也会查。

(pilot 样本=2 只够 smoke test,方法须能放大。)

## 二、深版编写方法:顶尖从业者视角的 4 条

一个 instructional designer + 机器视觉领域专家,不会"先写正文再找人试读",而是:

**(1) 会做、但容易被跳过的:**
- **逆向设计(Backward Design / UbD)**:先定"学会的标准"→ **先写练习/测评** → 正文只写
  "恰好供得起这些练习"的内容。(pilot 是事后发现错位;逆向设计从源头杜绝。)
- 建**跨章技能依赖图**,把对账变成全书前向不变量。
- 维护**领域误区清单**(BGR、(高,宽)、`img[y,x]`、uint8 溢出、HSV 的 H 范围、改后缀≠重编码、
  matplotlib 按 RGB…),每条**故意设计"撞一下再纠正"**。
- 对零基础用 **worked-example → 补全题 → 独立题** 的**渐隐**(认知负荷理论),而非"整段代码+出题"。
- **每个代码块在锁定环境真跑**,"预期结果"=机器核对的断言,不是手写声称。

**(2) 从最原始的一手源起手(不信已嚼碎的二手摘要):**
- `in/` 学校原始 .xls/.docx(直接重读,不信我们提炼的"硬约束")。
- **专业教学标准 + 1+X 机器视觉/计算机视觉应用 职业技能等级标准**原文。
- **OpenCV 官方文档 + 实际装的库的真实行为**(跑出来),非我们的 API 转述。
- **学生原始证据**:真实录屏 / 完整代码 / 原样报错(pilot 是种子,系统收)。
- **入门机器视觉岗位真实任务描述** + **海康 SDK / 真实部署案例**(ch08 相关性信号)。

**(3) 具体方法与工具:**
- 方法:UbD 逆向设计、认知负荷理论/4C-ID 渐隐、学习进阶/前置技能 DAG、修订版 Bloom 校准目标与题目层级、
  误区驱动设计、think-aloud 可用性测试、跨章检索练习+交错。
- 工具:**代码抽取-执行 harness**(抽 ```代码块 → 锁定 venv/容器跑 → 和"预期结果"逐一 diff)、
  **钉死环境**(Python 3.11 + opencv-contrib-python==4.11.0.86 的 requirements lock/容器)、**pytest/doctest**、
  **OBS**(录 think-aloud)、中文**可读性指标**、**git**、**追溯矩阵**(目标↔内容↔练习↔资源↔标准)。

**(4) 除作者之外、能证明"对"的外部检验:**
- **真实学习队列**(≥6–8 人、基础混合)自学,看客观指标:独立练习通过率、专注用时 vs 目标、
  按目标逐条后测掌握度、错误类型计数。
- **代码在锁定环境真跑**并产出所述输出(可复现机器核对)。
- **独立职教教师/SME** 对照标准评审。
- **对外部标准的可追溯清单**(第三方可核)。
- **海康**核 ch08 真实性;**出版社三审三校**。

## 三、每章编写检查单(动笔前逐步过)

> 这就是把上面方法落地的"每章 prompt"。写任何新章前按此 7 步走。

1. **扎根一手源**:把本章涉及技能的**能力要求**从〔专业教学标准 / 1+X 标准〕**逐条摘原文**,
   每个 API 查 **OpenCV 官方文档**;标出处,不用转述。
2. **逆向设计**:先写**本章目标 + 全部练习/测评**;对每道练习列出它需要的**每一个原子技能**。
3. **前向技能对账**:每个原子技能映射到"在哪教的"——前序章(已教)/ 本章正文(将补)/ **还没教过**。
   凡"还没教过"必须**先在正文补一个 worked-example 再考**。**输出"技能→位置"表。**
4. **写正文**:只写"恰好供得起这些练习"的内容;用 worked→补全→独立 渐隐;对每条已知误区
   (先列清单)设计一个"撞一下再纠正"。
5. **钉死并实测**:每个代码块给可运行版本,**在 Python 3.11 + opencv-contrib-python==4.11.0.86 全跑一遍、贴真实输出**,
   让"预期结果"等于机器输出。
6. **资源对账**:本章挂几个 📹微视频/🧪虚仿/🎬动画,登记台账 ID,**对齐全书下限轨道**(见一.2)。
7. **外部验证方案**:写明证明本章成立的外部检验(≥6 人 pilot + think-aloud + 指标、自动跑码结果、SME 对标)。
