# 文件结构与命名规范(NAMING)

> 本文件规定本项目的目录职责与文件命名规则,保证几个月、多次会话下**不长乱**。
> 语言约定:**路径 / 文件名一律用英文**,文件内容用中文(见 workspace 语言约定)。

---

## 一、四层目录职责(输入 / 规则 / 过程 / 输出)

借鉴函数三要素,并为"写书是有状态的长过程"补上「过程」一层:

| 目录 | 角色 | 放什么 | 能不能改 |
|---|---|---|---|
| `in/` | **输入** | 学校下发的原始材料(计划表、通知、模板、答疑图) | 🔒 只读,**不改不删** |
| `plan/` | **规则** | 支配"怎么做"的东西:`PLAN.md`、`OUTLINE.md`、章节模板、本规范 | ✅ 常改 |
| `draft/` | **过程(在制品)** | 正在写的章节初稿、正在开发的资源 | ✅ 频繁改 |
| `out/` | **输出(交付)** | 章节定稿、资源成品、给学校的月度提报/佐证 | ✅ 定稿后追加 |

- `draft/` 里的东西**做完 → 复制/移动到 `out/` 对应位置**,即"函数处理完 → 返回输出"。
- `in/` 是只读边界;学校再发文件,一律丢进 `in/`。

---

## 二、核心命名原则

1. **语义命名为主,版本交给 git**。文件名回答"**这是什么**",不回答"什么时候做的"。
   - ❌ 禁止:`ch02_v3.md`、`ch02_final_final.md`、`ch02_20260713.md`(git 已管版本)。
2. **时间戳只用于"时间锚定"的产物**(其身份由"哪个月/哪天"定义),典型 = 月度提报/佐证。
3. **通用格式**:全小写、英文、下划线 `_` 分隔;不用空格、不用中文文件名。
4. **章节号补零**:`ch01`、`ch02`……保证文件按序排列。
5. **用日期就用 ISO 8601**(`YYYY-MM-DD` 或 `YYYY-MM`),文本排序即时间排序;禁止 `13-07-2026`。
6. **例外**:`in/` 里学校发来的原始文件**保留原名**,不改。

---

## 三、各类文件命名

### 章节(`draft/chapters/`,定稿后进 `out/chapters/`)
- 格式:`ch{NN}_{slug}.md`
- 例:`ch02_the_secret_of_images.md`
- 草稿与定稿**同名**,靠所在目录区分阶段(`draft/` vs `out/`)。

### 配套数字资源(`draft/resources/`,成品后进 `out/`)
- **台账 ID**:沿用 `OUTLINE.md` 里的 `{章}-R{序号}`(如 `2-R1`),用于清单登记。
- **文件名**:`ch{NN}_{type}_{slug}.{ext}`
  - `type` 取值:`video`(微课) / `anim`(动画) / `sim`(虚拟仿真) / `code`(代码) / `img`(图) / `slide`(课件)
  - 例:`ch02_video_pixel_zoom.mp4`、`ch02_sim_pixel_lab/`(虚仿常是一个文件夹)、`ch02_code_read_show_save.py`

### 月度提报 / 佐证(`out/reports/`)
- 格式:`{YYYY-MM}_{content}.md`(时间锚定,故用日期前缀)
- 例:`2026-07_progress.md`、`2026-11_ch02_佐证.docx`(交付学校时再按其模板另存)
