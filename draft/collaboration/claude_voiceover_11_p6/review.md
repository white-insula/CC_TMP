## 四、读法处理与对正式讲解词的改动

正式讲解词原文见 `texts/narration_original.txt`，TTS 实际输入见 `texts/tts_input_spoken.txt` 和 `scripts/tts_input.json`。

| 内容 | 处理 |
|---|---|
| 文件名 | **画面适配**：原文 numpy_image.py，录屏实际是 create_img.py，按画面读作“create，下划线，I M G，点 P Y”。正式脚本未改。 |
| NumPy | 词典追加 `numpy → n ah m p ay`（读作 num-pie），避免模型逐个字母念 N-U-M-P-Y |
| uint8 | “U int 八”，词典追加 `int → ih n t` |
| dtype / ndarray | 分别读“D type”“N D array” |
| imshow | 词典追加 `imshow → ih m sh ow`（im show）。函数名是 imshow，不读成 image show |
| cv2 / np / img | “C V 二”“N P”“I M G”按字母读 |
| 300/400/3 | 写成汉字“三百、四百、三”，避免数字规范化歧义；宽高顺序未颠倒 |
| 措辞微调（为发音清楚，不改含义） | ① “新建文件” → “新建**一个**文件”；② “NumPy 数组” → “NumPy **的**数组”（英文词直接接“数组”时，机器转写两次都把“数组”听成“手组”）；③ “zeros 的意思是全部填零，零就是黑色” → “**这里** zeros 的意思是全部填零，**而**零就是黑色”（第二个“零”在多种噪声参数下都被转写成“您”，句首的 zeros 也常被吞掉） |

教学含义保持不变：创建 300 高 × 400 宽 × 3 通道的 uint8 全零数组；type 为 ndarray；shape 为 (300, 400, 3)，dtype 为 uint8；imshow 显示黑图。没有加入背景音乐、环境噪声、开场或总结。

## 五、机器转写核对（不是人工试听）

用两个离线 ASR 模型转写合成结果（日志见 run_log.txt）。它们对“中文里夹英文”的识别本身就不可靠，结果只能用来定位**可能**不清楚的词：

- **中文部分与数字**：两个模型都正确转写了“下面动手 / 新建一个文件 / 下划线 / 括号里写高三百宽四百通道三 / 而零就是黑色，所以我们得到了一张全黑的图 / 说明它就是……的数组 / 分别是三百四百三 / 你会看到一个高三百宽四百的黑色窗口”（SenseVoice，最终版本）。
- **英文与字母，机器常识别不出**：
  - I M G 常被转写成“m g”，N P 常被转写成“m p”；
  - NumPy 被转写成“南派/那派”，与真实读音 num-pie 接近，可能是 ASR 偏差；
  - “N D array”被转写成“any/and diary”，“type”有时被转写成“太”，“U int 八”被转写成“unit 八”；
  - “C V 二”后面接“和”时偶尔被吞。

**请试听重点**：第 1 段 I M G、P Y；第 2 段“C V 二，和 numpy”；第 3 段“N P 点 zeros”“U int 八”“这里 zeros…”这一句（paraformer 在这句出现了重复转写，SenseVoice 正常）；第 4 段“N D array”“shape”“D type”。

**合成的随机性**：VITS 合成有随机性，每次结果略有不同。已把噪声参数从默认的 0.667/0.8 降到 0.3/0.5，两次重复合成的机器转写更稳定。提交的音频是最终一次运行的结果，哈希记在 run_log.txt。
